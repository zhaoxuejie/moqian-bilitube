# B 站接口探测记录

探测时间：2026-11-04
探测目的：确认"B 站 AI 大模型视频精选"方案的接口可用性、限速与登录态依赖。

## 1. 结论

| 能力 | 接口 | 未登录可用 | 说明 |
| ---- | ---- | ---- | ---- |
| 关键词搜索 | `x/web-interface/wbi/search/type` | ✅ | 单关键词上限 1000 条（50 页 × 20），不用 wbi 签名也能通 |
| 视频详情 | `x/web-interface/view?bvid=` | ✅ | 标题、UP、时长、播放、收藏、投币、分区齐全 |
| 评论 | `x/v2/reply?type=1&oid=<aid>` | ✅ | 返回热评，用于口碑判断 |
| 弹幕 | `x/v1/dm/list.so?oid=<cid>` | ✅ | 返回 deflate 压缩 XML，单次约 1200 条 |
| 字幕 | `x/player/v2?bvid=&cid=` | ⚠️ 未验证 | 未登录返回空列表，需登录 Cookie 才能确认 |

请求头必须带 `Referer: https://www.bilibili.com/`，否则容易被风控。

## 2. 样例观察

搜索"大模型 入门"的第一条结果：

- 标题：`【全748集】目前B站最全最细的AI大模型零基础全套教程，2025最新版，包含所有干货！七天就能从小白到大神！少走99%的弯路！`
- 播放 387 万、收藏 17 万、时长 931 分钟

这条样本直接说明了产品的核心难题：**高播放 + 高收藏并不等于高质量**，标题堆砌"最全/最细/七天/干货"是典型的引流话术。三层评估里"文案特征识别"必须单独占一项。

## 3. 待验证项

1. 登录态下字幕接口是否返回 AI 字幕，覆盖率大概多少
2. 弹幕接口是否按分段返回、单视频总量上限
3. 搜索接口在密集请求下的限速阈值（当前按 1–2 req/s 设计）
4. 评论分页上限与深分页是否可行

## 4. 对架构的影响

- 采集层可以全部走公开接口，无需登录（字幕除外）
- 字幕不可得时，第三层评估降级为"弹幕 + 评论 + 简介"文本，需在卡片上标注评估依据
- 需要设计统一的"评估依据"字段，避免用户误以为所有卡片都读过视频内容

## 5. 实采阶段的新发现（2026-11-04，TASK-004）

### 5.1 收藏率口径不统一，可以超过 100%

同一批数据里：

| BV 号 | 播放 | 收藏 | 收藏率 |
| ---- | ---- | ---- | ---- |
| BV1boqBBEENs | 5,338,241 | 2,664,146 | 49.9% |
| BV1ug3qzhEp9 | 1,141,309 | 1,286,533 | **112.7%** |

收藏数大于播放数，说明两者口径不同（播放是去重口径，收藏更像累计次数）。**任何"收藏率 > X%"的绝对阈值都不可靠**，必须用分位，见 ADR-009。

### 5.2 未登录评论接口只返回 3 条

视频实际有 622 条评论，但 `/x/v2/reply` 在未登录下 `replies` 只返回 3 条，翻到第 2 页直接返回 0；`page.count` 仍是 622。

结论：**评论层在未登录状态下基本不可用**，第二层评估的实际输入是"标题 + 简介 + 弹幕（约 1200 条）+ 3 条热评"，见 ADR-010。

### 5.3 单关键词搜索上限

- `numResults` 固定上限 1000，对应 50 页 × 20 条
- 按收藏排序与按播放排序结果**重合度不高**，两种排序都要跑

### 5.4 首轮全量采集的真实数据（250 页 / 3652 条）

| 指标 | 数值 |
| ---- | ---- |
| 成功页 | 250 |
| 失败页（HTTP 412） | 27 |
| 写入记录 | 4240 |
| 去重后视频 | 3652 |
| 标题命中 AI 相关词 | 57.6% |
| 时长 < 3 分钟 | 811（22%） |
| 时长 > 3 小时 | 536（15%） |
| 标题含"合集/全套/大全" | 117 |

**结论**：

- 搜索结果的噪音比预期大，播放量前 5 全是娱乐视频，必须做相关性过滤
- `coin` 字段在搜索接口里缺失，投币率要靠详情接口补
- 即使降到 0.4 req/s，仍有约 11% 的页返回 412，需要失败页重试机制
