- 编号：TASK-002

## 执行步骤

1. 封装统一的 B 站客户端：直连（不走代理）、浏览器 UA、`Referer: https://www.bilibili.com/`
2. 实现令牌桶限速，默认 1.5 req/s，可配置
3. 实现重试与退避：网络异常与 `-352` 指数退避（1s、2s、4s），最多 3 次；`-403`/`-404` 不重试
4. 实现接口方法：`search_videos`、`video_detail`、`comments`、`danmaku`、`subtitles`（字幕默认不带 Cookie）
5. 统计每次调用的状态码分布与 `-352` 比例，供采集报告使用
6. `-352` 比例超过 5% 时抛出可中断信号，触发暂停

## 验收标准（布尔判定）

- [ ] 调用 `video_detail` 返回 `code=0` 与完整统计字段
- [ ] 连续 5 次请求的间隔不小于 0.6 秒（限速生效）
- [ ] 模拟 `-352` 时触发退避并重试，3 次后抛出明确异常
- [ ] 模拟 `-403`/`-404` 时不重试、直接返回失败结果
- [ ] 客户端默认不携带 Cookie；显式传入时才携带
- [ ] 单元测试全部通过，网络调用全部 mock

## 评测方案

- 单元测试：mock HTTP 响应，覆盖成功、`-352`、`-403`、超时四种场景
- 真实 smoke：对 1 个已知 BV 号调用详情接口，断言 `code=0`
- 数据校验：记录限速用时，核对请求间隔符合预期
