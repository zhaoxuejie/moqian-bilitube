## 执行步骤

1. 建立可配置词表 `config/rules.json`：AI 相关白名单词、引流黑名单词、合集拼凑标记词、允许分区列表
2. 实现 `filter` 子命令：读取 `raw_videos`，逐条判定 `passed` / `rejected`
3. 过滤规则（命中任一即拒绝，并记录原因）：
   - 标题不含任何 AI 相关词
   - 标题命中引流词（最全 / 最细 / 零基础全套 / 七天速成 / 99% 的人不知道 等）
   - 时长 < 180 秒
   - 分区不在允许列表
   - 标题含合集 / 全套 / 大全 / 搬运 且时长 > 3 小时
   - 同一 UP 主通过数量超过 5 条（按播放量取前 5）
4. 结果写入 `videos` 表：`status` 与 `reject_reason`，保持幂等
5. 输出过滤报告：通过数、拒绝数、各原因命中分布、通过样本 20 条

## 验收标准（布尔判定）

- [ ] 对当前 3652 条候选执行，输出通过率与拒绝原因分布
- [ ] 每条被拒记录都能查到唯一且可读的 `reject_reason`
- [ ] 规则全部来自 `config/rules.json`，改词表不需要改代码
- [ ] 重复执行结果一致（幂等）
- [ ] 人工抽检 30 条，判定准确率 ≥ 80%
- [ ] 单元测试覆盖每条规则

## 评测方案

- 单元测试：为每条规则构造正反样例
- 人工抽检：随机 30 条，记录准确率，低于 80% 则调整词表
- 数据校验：通过数 + 拒绝数 = 候选总数
