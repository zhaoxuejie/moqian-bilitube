# 数据源可行性实测报告（V2EX × B站）

实测时间：2026-11-04
实测目的：验证"V2EX 评论区被反复推荐的 B 站视频"这一信号是否足以支撑首版 500 个视频的目标，并给出可复现的估算方法。

## 1. 结论先行

| 指标 | 估算值 | 说明 |
| ---- | ---- | ---- |
| V2EX 含 "bilibili" 的主题 | 10,448 | sov2ex 索引口径 |
| 含 B 站视频链接的主题 | ≈ 9,200 | 抽样 78% 命中 × 11,765 |
| 链接实例总数 | ≈ 12,000 | 1.04 链接/主题 |
| 去重后视频数 | ≈ 10,000 | 主题内基本不重复 |
| 被提及 ≥3 次 | ≈ 480 | 抽样占比 4.8% |
| 被提及 ≥3 次且跨 ≥3 个月 | ≈ 240 | 抽样占比 2.4% |
| 被提及 ≥2 次且跨 ≥2 个月 | ≈ 1,200 | 抽样占比 12% |

**判断：500 个目标偏高，但信号没有塌。** 按最严阈值（≥3 次 × ≥3 个月）约 240 个，按放宽阈值（≥2 × ≥2）约 1,200 个。建议 v1.0 目标下调到 200–300，把"经典"（≥3×≥3）与"推荐"（≥2×≥2）做成两档，而不是二选一。

## 2. 方法

1. 用 sov2ex（第三方 V2EX 站内搜索，覆盖主题与回复正文）取 `q=bilibili.com/video` 的命中总量与分页结果
2. 抽取 50 个主题，用 V2EX 公开 API `api/replies/show.json` 拉取全部回复
3. 从主题正文 + 回复中正则抽取 `BV` / `av` / `b23.tv` 链接并去重
4. 对抽中的 42 个视频回查 sov2ex，得到每个视频在站内的被提及次数与跨月分布

## 3. 关键发现

### 3.1 V2EX 站内搜索已经不可用

`https://www.v2ex.com/search?q=bilibili` 会 302 到 `https://www.v2ex.com/go/search`（"搜索引擎技术研究"节点）。用户在前台搜不到东西，这不是搜索词的问题，是入口已经变了。

**影响**：发现层（找出候选主题）不能依赖 V2EX 官方搜索，只能靠 sov2ex，或按主题 id 全量遍历。

### 3.2 候选规模比预想小得多

真正需要抓的是约 1.2 万个候选主题，不是百万级全站。按 1 req/s 计算，全量抓取约 2.5–3 小时，单机完全可承受。这比"全站扫一遍"的方案便宜两个数量级。

### 3.3 绝大多数视频只被提到一次

42 个视频的平均被提及次数是 1.17。这是与 HackerTube 最大的差异：HN 有跨十年的"经典 talk 共识"，V2EX 的 B 站链接基本是"一次性佐证"。

### 3.4 链接语境混杂

抽样的 50 个主题里，除了真正的视频推荐/讨论（剧评、发布会、纪录片、技术演示），还混着三类噪音：

- 技术问题：`video 标签播不动`、`B 站裸域证书`、`弹幕脚本`
- 自荐推广：`中转站推广`、`工具发布`
- 求资源：`求 XX 纪录片`

正则能抽到链接，但抽不到"是否在推荐"。这层必须靠 LLM 标注过滤，正是 PRD 模块 E 的职责。

## 4. 局限与风险

1. **依赖第三方索引**：sov2ex 的覆盖度、更新频率、索引时间范围都不透明。若它只覆盖部分历史主题，上面的数字是低估。
2. **样本量小**：50 主题 / 42 视频。跨月占比 2.4% 实际是 1/42，置信区间很宽（大致 0%–12%）。
3. **分母口径不精确**：`bilibili.com/video` 是分词后的多 token 匹配，不是精确 URL 匹配，约 22% 的命中主题其实没有 B 站链接。
4. **网络环境**：本机访问 V2EX 必须走系统代理 `127.0.0.1:7890`；PowerShell 的 `Invoke-WebRequest` 不稳定，`curl.exe -x` 才可靠。

## 5. 对方案的影响

- 采集规模从"全站千万级评论"修正为"约 1.2 万个候选主题、十几万条回复"，工期与成本都下降
- 首版目标从 500 调整为 200–300，阈值默认 ≥2 作者 × ≥2 月，另设"经典"标签（≥3 × ≥3）
- 发现层明确依赖 sov2ex，需要在架构 ADR 里记录这个外部依赖与失效预案
- LLM 标注里必须新增"是否为推荐语境"的判断，否则噪音会把榜单污染

## 6. 复现方式

临时脚本：`%TEMP%\bilitube-spike\spike.py`（未入库，仅用于本次实测）
运行参数：12 页 × 50 条候选主题、抽样 50 个主题、回查 42 个视频、请求间隔 0.75s
结果文件：`%TEMP%\bilitube-spike\results.json`
